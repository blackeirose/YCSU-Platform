# YCSU Platform v1.3.0 — Owner-only Product Links

Released 2026-09-11 after production guest API and DOM security acceptance. v1.2.0 was separately released with YuCheng's confirmed real-device reorder acceptance.

## Behavior

Guests see the same Registry-driven cards and public previews, with no Product/planned/GitHub/Tracker/Docs/Roadmap links or reorder controls. The backend omits protected fields entirely and redacts endpoint-bearing text. The existing owner Supabase identity unlocks full links, preview launch and persistent ordering. Non-owner authentication does not grant access. Logout immediately removes owner data and controls, including across tabs.

## Enforcement and artifacts

- Existing registry-ops v5 provides read-public and UUID-authorized read-owner; owner browser CRUD stays denied. Existing management-key operations remain available.
- Migration 20260911225043 revokes table and explicit column privileges from PUBLIC/anon/authenticated and removes public SELECT. RLS remains enabled. No new views or security-definer read bypasses.
- Public schema 1.3: id, slug, name, shortName, description, category, platformLayer, maturity, deployment, visibility, operationalStatus, version, versionSource, featured, archived, certification, lastUpdated, statusNote, sortOrder. Six URL fields are absent in public data, not null.
- Public-only fallback replaces the full snapshot. The live manifest becomes a fictional example. Deterministic dist output excludes docs, migrations, tests, manifests and full exports; no-store prevents response caching. Owner records stay in memory.
- MAIN's self-preview is manually refreshed from a guest-only production directory region. No capture automation, new hosting site, DNS change or other-app login changes.

## Security limitations and recovery

This protects MAIN's current runtime Registry interface. Domains can remain in intentional public architectural documentation, Git history and older immutable deployments; downstream products enforce their own access. Previously downloaded owner information cannot be recalled. No shared SSO, roles, dashboard or downstream authentication was implemented.

Supabase advisor INFO RLS-with-no-policy is intentional default deny ([reference](https://supabase.com/docs/guides/database/database-linter?lint=0008_rls_enabled_no_policy)). The pre-existing project-wide leaked-password-protection warning remains ([remediation](https://supabase.com/docs/guides/auth/password-security#password-strength-and-leaked-password-protection)).

Never recover by restoring public raw-table grants, a full public fallback or a repository-root deployment. Preserve the v1.3 read contract; public-safe cards may remain available without owner links during an owner-path outage.
